# M2: Xero read-only mirror and deal files

Xero stays the book of record. M2 only reads from Xero: the client has a single GET method, the app asks
Xero for read-only scopes, and `tests/unit/xero-no-writes.test.ts` fails the build if a non-GET call to the
accounting API appears anywhere in the code.

## What M2 delivers

| Area | Where |
|---|---|
| Schema: contacts, quotes + lines, invoices + lines, payments, attachment metadata, sync cursors, OAuth states, deal files | `supabase/migrations/0006_xero_mirror.sql` |
| OAuth connect (read-only scopes), encrypted tokens, locked single-use refresh | `lib/integrations/xero/{config,oauth,connection}.ts`, `/admin/integrations/xero/connect` and `/callback` |
| GET-only client with rate-limit headroom and backoff | `lib/integrations/xero/client.ts` |
| Mappers (.NET and ISO dates, money with its own currency) and sync plan | `lib/integrations/xero/{mappers,plan}.ts` |
| Sync: backfill (everything changed since `XERO_BACKFILL_FROM`, plus open quotes and unpaid invoices) then incremental by `If-Modified-Since`; resumable page by page | `lib/integrations/xero/sync.ts` |
| Webhook: signature over the raw body, raw event stored once, fetch queued, 200 fast | `app/api/webhooks/xero/route.ts` |
| Jobs: outbox, `job_runs`, `/api/jobs/xero-sync` and `/api/jobs/outbox` behind `JOB_SECRET` | `lib/jobs/*`, `app/api/jobs/[queue]/route.ts`, `supabase/scheduler.sql` |
| Deal files: one row per quote no linking quote, invoices, VIN, DEAL, RFI, Job Card, Inspection, Release, Delivery Note | `lib/deal-files/*` |
| Admin: Xero health (connection, token expiry, rate headroom, webhooks, sync state, runs, month check), Quotes, Invoices, Deal files timeline | `/admin/integrations/xero`, `/admin/xero/*`, `/admin/deal-files` |
| Quote picker on DEAL, RFI and Job Card (staff search; public forms only confirm an exact match) | form engine |

## Setup (one time)

1. **Xero app** at developer.xero.com → New app → Web app.
   - Redirect URI: `https://trailer-eta.vercel.app/admin/integrations/xero/callback` (shown on the health page).
   - Webhooks: delivery URL `https://trailer-eta.vercel.app/api/webhooks/xero`, events Invoices and Contacts.
     Xero sends an "intent to receive" check when you save; the endpoint answers it.
2. **Vercel env (Production)**, all marked Sensitive:
   - `XERO_CLIENT_ID`, `XERO_CLIENT_SECRET`, `XERO_WEBHOOK_KEY` (from the Xero app)
   - `ENCRYPTION_KEY` (32 random bytes, base64) encrypts the Xero tokens. Keep a copy: losing it means reconnecting.
   - `JOB_SECRET` (at least 32 random characters) protects `/api/jobs/*`.
   - Optional: `XERO_TENANT_ID` (pick one organisation if the login sees several), `XERO_BACKFILL_FROM` (default 2025-01-01).
   - Redeploy after setting them.
3. **Scheduler**: run `supabase/scheduler.sql` in the Supabase SQL editor with the two placeholders replaced.
4. **Connect**: an admin opens `/admin/integrations/xero`, clicks Connect to Xero and approves read-only access to
   the live organisation. Then Sync now (or wait for the schedule). The backfill takes several runs; the health page
   shows progress per entity.
5. **Acceptance**: on the health page, Check a month against Xero for a full past month: every line must say Match.

Generate secrets with:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

## Rate limits

Xero allows 60 calls a minute and 5,000 a day per organisation. A run stops early when fewer than 5 calls are left in
the minute or 300 in the day, and the next scheduled run continues from its saved cursor. Daytime runs (every 15 minutes,
07:00 to 22:00 SAST) sync invoices and payments only; the nightly run syncs everything and attachment metadata.

## Matching rules (deal files)

- Quote no: DEAL `QUOTENO`, RFI `QuoteNo`, Job Card `QuoteNo`, Xero `QU-<no>`. Stored and matched without the `QU-` prefix.
- Invoices: a sales invoice whose Reference is the quote no (Make's RFI flow sets it), or whose Reference is the trailer's
  VIN (Make's Delivery Note flow writes the VIN there).
- Release Form `INVNO` and Delivery Note `INVOICENO` match the invoice number with or without `INV-`.
- Delivery Note `QuoteNo` is a lookup of an RFI entry; Inspection matches by VIN.
- When a form has several entries for one quote no, the newest wins. Deal files are never deleted.

## Not in M2

Writes of any kind to Xero (M3), attachment downloads, credit notes.
