# M6: Stock control (units by VIN, dispatch, branch matrix, invoice to reserved/sold)

Source: `docs/source/BUILD_PLAN_trailer_stock.md` (the ChatGPT review build, reverse engineered). That plan describes a
stand-alone app. This platform already has most of what it builds from scratch, so M6 maps it onto what exists.
**Design is ours**: the UI-step-1 tokens and `components/ui` (see CLAUDE.md "Repo notes (UI handoff, step 1)"), not the
review build's teal look. Copy (messages, labels) follows the stock plan where it specifies text.

## 1. What changes from the stock plan

| Stock plan | M6 |
|---|---|
| Cognito webhook feeds `deals` | Derived from our own **DEAL** entries (job on DEAL Submit/Update + backfill). No Cognito webhook. |
| Make / Xero webhook feeds invoices | Derived from the **Xero mirror** (`xero_invoices`) after each sync/webhook upsert. No Make. |
| Own auth, `profiles`, roles superuser/admin/dispatcher/branch | Our orgs, memberships, `can()`. Superuser = `admin`. New role `factory` (dispatch). Branch scoping deferred. |
| `activity`, `deal_audit` tables | `audit_log` (append-only, ids only) with `stock.*` actions; the Activity page renders it. |
| `integration_deliveries`, Connections page, webhook secrets | Not needed: Xero integration page already shows sync state. |
| `app_settings` singleton (`integration_live`) | Org `app_settings` keys `stock.*` (server-only writes, like 0009: restrictive RLS policies in 0011 block client insert/update/delete, even for org admins). |
| Simulated / manual invoice form | Manual apply kept for admins (invoice not in Xero yet), same rules, audited. |
| Single-tenant tables | Every table org-keyed with RLS (CLAUDE.md non-negotiable 2). |
| `customer_name` on deals | Not stored. Stock tables hold no personal data (DEAL is an encrypted form). |

## 2. Data (migrations)

- `0010_stock_role.sql`: `alter type app_role add value 'factory'` (alone: a new enum value cannot be used in the same transaction).
- `0011_stock.sql`:
  - `stock_locations(org_id, id text, name, is_factory, sort_order)`: FACTORY, JHB, CPT, DBN seeded for the default org.
  - `stock_models(org_id, part_number, description, category, active, sort_order)`: the 52 models in the plan's order and spelling (keep "SINGEL", "CRADEL", "Dubbel axel").
  - `stock_deals(id, org_id, entry_id -> entries, year, number, location_id, model_part, quote_number, accessories text[] <= 10, status awaiting_dispatch|dispatched|dismissed, unit_id, dismissed_reason, dispatched_at, created_at, updated_at)`; unique (org_id, year, number), unique (org_id, entry_id). `dismissed_reason` is the current dismissal only.
  - `stock_deal_dismissals(id, org_id, deal_id, reason, dismissed_by, dismissed_at)`: append-only dismissal history written by `stock_dismiss_deal` (no update/delete grants, not even for the server), so a reason survives restore and re-dismiss. The `stock.dismiss` audit row carries its `dismissal_id` (the reason itself never goes into audit meta).
  - `stock_units(id, org_id, vin, vin_norm generated stock_norm_vin(vin) unique per org, deal_year, sequence, deal_id, model_part, location_id, status available|reserved|sold, invoice_number unique per org when not null, xero_invoice_id, dispatch_date, accessories text[] <= 10, notes, sold_at, created_by, created_at, updated_at)`. `stock_norm_vin` = upper case with whitespace **and** invisible characters (NBSP, BOM, zero-width spaces/joiners, direction marks) removed: Postgres `\s` keeps those, and pasted VINs carry them. The RPCs and the invoice reference match use the same function; `lib/stock/vin.ts` uses the same character class (tests check the text and that both strip exactly the same code points).
  - `stock_invoice_exceptions(id, org_id, xero_invoice_id, invoice_number, reference, reason, unit_id, created_at, resolved_at, resolved_by, resolution)`; unique open exception per (org, invoice, reason).
  - RPCs (security definer, `set search_path = ''`, check membership + role inside, write `audit_log`): `stock_dispatch_unit`, `stock_move_unit` (factory to branch / transfer), `stock_correct_unit`, `stock_dismiss_deal` / `stock_restore_deal` (admin only, reason required), `stock_apply_invoice` (used by the job and the manual form).
    - A deal clears only when its unit reaches a branch: a dispatch to a branch against it, or `stock_move_unit` Factory -> branch with it. Dispatching (or moving) to the Factory with a deal raises `INVALID_INPUT` (`field: location, reason: factory_with_deal`); register the unit at the Factory without the deal.
    - `stock_correct_unit` (admin) repairs a dispatch made against the wrong deal: `{"deal": {"year": y, "number": n}}` relinks (old deal back to awaiting dispatch, new deal checked like a dispatch and cleared, unit deal_year/sequence follow; not for a unit at the Factory), `{"deal": null}` unlinks. Audited with the new and previous deal ids/year/number. Error codes as in the stock plan section 6.1 (`VIN_EXISTS`, `DEAL_NOT_FOUND`, `DEAL_DISMISSED`, `DEAL_ALREADY_DISPATCHED`, `VIN_NOT_FOUND`, `UNIT_LINKED_OTHER_INVOICE`, `INVOICE_LINKED_OTHER_UNIT`).
  - Clients: select for org members (stock.read); no direct insert/update/delete on stock tables; writes only through the RPCs or the service role after `requirePerm`.
  - View `stock_matrix` (security_invoker): per model x location qty (available + reserved) and reserved count, sold excluded.
- Every new table goes into `tests/db/rls.test.ts`.

## 3. Rules (pure, `lib/stock/*`, unit tested)

- `normalizeVin` (same character class as `stock_norm_vin`), `extractVin(reference, knownVins)` (exact normalised match first; else the one known VIN contained in the reference; else none/ambiguous).
- KPIs (plan 5.2): stock across branches (branch, available|reserved), ready to sell, reserved, at factory (not sold); sold excluded everywhere but searchable.
- `dealFromEntry(data, entry)`: year = year of `DATECREATED` (fallback: entry created date, Africa/Johannesburg); number = DEAL entry number; location from `COLLECTIONLOCATION` (JHB->JHB, DUR->DBN, CPT->CPT); model = first `PARTNO1..8` matching a model part number (case/space-insensitive); accessories = the other non-empty `LINE` descriptions, max 10; quote = `QUOTENO`. ASSUMPTION: the stock plan's "sequence number" is the DEAL entry number. Unknown model -> deal shows "Model not recognised" and dispatch asks for the model.
- `invoiceOutcome(invoice, unit)`: AUTHORISED/SUBMITTED with amount due > 0 (incl. partly paid) -> reserved; PAID (amount due 0) -> sold; VOIDED/DELETED, credit notes, missing/unknown/ambiguous VIN, unit linked to another invoice, invoice linked to another unit -> exception, no change. DRAFT -> ignored.
  - Which sales invoices are stock invoices: the reference names a known VIN, **or** a line's item code is a model part number, alone or followed by a suffix after a separator (`3000D`, `CTLL1-GWM`, `3000D/RED`, `BOX02 ISO`; `isModelItemCode`). `item_codes` is a required input: the job passes the mirror's `xero_invoice_lines.item_code` values ([] when none).
  - **Known limit (rule):** a unit invoice whose reference names no known VIN (empty, or a mistyped VIN) **and** whose lines carry no model item code cannot be told apart from a parts/service invoice, so it is ignored, not an exception, and the unit stays available. Unit sales must use the model's item code in Xero for missing/unknown VIN exceptions to appear. Tested as such in `tests/unit/stock-invoice.test.ts`.

## 4. Settings ("Pilot setup", `/admin/stock/setup`, admin)

- `stock.deals_from` (date): only DEAL entries created on/after it become stock deals. Unset = no deals imported (avoids ~550 historical deals showing as outstanding).
- `stock.invoice_rules`: `off` | `preview` | `live`, default **preview**: the job records what each invoice would do (shown on Invoice review) but changes no unit. `live` needs a typed confirmation and is audited (same pattern as Xero actions, server-only writes).
- Both keys are written only by the setup server action (requirePerm `stock.manage`, then the service role). RLS (0011 `settings_no_client_stock_*`) rejects any client insert/update/delete of `stock.*` keys, including an org admin's own token through PostgREST; members can still read them.
- Opening stock: CSV upload (VIN, model, location, status, invoice, deal year, sequence, dispatch date, notes) -> dry-run report (counts, duplicate VINs, unknown models/locations) -> apply. Idempotent on VIN.
- "Rebuild deals" button (enqueue the backfill job).

## 6. Jobs

- `stock.deal-sync` (payload: entry id) enqueued from `afterSave` for DEAL Submit/Update; `stock.deals-backfill` (all DEAL entries since `stock.deals_from`, resumable).
- `stock.invoices` after each sync/webhook upsert batch (invoice ids) and nightly: applies `invoiceOutcome` per `stock.invoice_rules`; idempotent (same invoice state twice = no-op).
- All jobs record `job_runs`, never log VINs with personal data (VINs are not personal data; customer details never touched).

## 7. Permissions

`stock.read` (admin, staff, reviewer, factory), `stock.dispatch` (admin, staff, factory), `stock.export` (admin, staff), `stock.invoices` (admin, staff, reviewer: Invoices tab and exceptions queue; same audience as RLS on `stock_invoice_exceptions`, tested against `can()`), `stock.manage` (admin: dismiss/restore, correct/relink, transfer, manual invoice, exceptions, setup).

Factory staff hold `admin.access` but not `entries.read`: the admin home shows them no form list (`homeShowsForms`), since every link there opens an entries page.

## 8. Acceptance (from the stock plan, adapted)

Duplicate VIN blocked incl. sold; dispatch against a deal clears it; dismissed deal blocks dispatch; already dispatched deal blocks a second dispatch; dispatch without a deal never clears a deal; unpaid -> reserved stays in counts with amber marker; paid -> sold leaves counts but stays searchable; unit linked to another invoice -> exception, no change; voided invoice -> exception; preview mode changes nothing; non-admin cannot dismiss/restore or change setup (server and RLS); cross-org isolation on every stock table; DEAL submit creates exactly one stock deal (resubmit/update updates it).

## 9. Open questions (defaults in brackets; rules are switchable)

1. Voids/credit notes on a reserved or sold unit [exception queue, no automatic change].
2. Partial payment threshold [any amount due > 0 = reserved].
3. Branch transfers and returns to factory [admin transfer with audit].
4. Branch users see only their branch [no, all branches].
5. Is the stock "sequence number" the DEAL entry number, and does the year come from DATE CREATED [yes, yes].
6. One deal = one unit [yes].
7. Factory units registered before a deal exists [yes: dispatch to Factory without the deal, later move to a branch with it, which clears the deal].
8. "Pilot setup" in the review build: confirm it is the start date + opening stock + rule mode [assumed].

## 10. Built: deals and dispatch (branch m6-dispatch)

### DEAL -> stock deal sync (section 6)
- `stock.deal-sync` (payload `{ entryId }`): enqueued by `runAction` `afterSave` for DEAL **Submit / Update / Action**
  (`lib/stock/deal-jobs.ts` `enqueueStockJobsForSave`, next to the M3 Xero hook) and by `systemUpdateEntry` (the quote
  import fills the DEAL's part numbers). The job decrypts the DEAL server-side (`lib/forms/entries.ts`), asks
  `stockDealFor` (pure, `lib/stock/deal-sync.ts`) what the deal should hold and `planDealSync` what to write, then writes
  with the service role, every query filtered on the job's org. `job_runs` row per run (counts only).
- Scope: only non-draft DEALs dated (DATE CREATED, else the entry's created date in Africa/Johannesburg) on/after
  app_settings `stock.deals_from`. Unset = nothing is imported (and nothing is read).
- Never downgrades: status, unit and dismissal columns are never written by the sync. Branch, model, quote number and
  accessories follow the DEAL. Year and number follow the DEAL only while the deal awaits dispatch and was never
  dismissed. A deal that falls out of scope (start date moved later, entry back to draft) is removed only while it is
  untouched (awaiting dispatch, no unit, no dismissal history); otherwise it is kept.
- Conflicts (year + number held by another DEAL's deal) are left alone and counted in the run; a deal row whose entry
  was deleted (`entry_id` null) with the same year + number is adopted.
- `stock.deals-backfill` (payload `{ from: <last DEAL entry number done> }`): every DEAL entry in number order, 100
  per batch, ~20 s per run, re-enqueues itself until done (resumable, idempotent). The Setup page's "Rebuild deals"
  enqueues it (`enqueueDealsBackfill`, uniquePending). Unreadable entries (decryption failed) are counted, not fatal.
- Stored: entry id, year, number, branch id, model part number, quote number, accessory line descriptions. No
  customer data.

### /admin/stock/deals (stock.read; plan 7.2)
- KPI cards: All branches + each branch, "Awaiting dispatch · {year}" (count queries through RLS); a card filters
  the table to its branch.
- Filters (GET, URL-synced): Year (oldest deal year .. this year), Branch, Show dismissed (= only dismissed).
  50 per page, newest deal number first. Footer "{n} outstanding deals · Dispatches without a deal number do not
  clear this list."
- Rows: YEAR / DEAL (links to the DEAL entry for `entries.read`; factory staff see plain text), branch ("No branch"),
  model ("Model not recognised" chip), quote number, status chip, **Dispatch →** (stock.dispatch) to
  `/admin/stock/dispatch?year=&number=`. Admin (stock.manage): **Dismiss** opens a dialog with a required reason
  (max 200), **Restore** on dismissed rows. Both call `stock_dismiss_deal` / `stock_restore_deal` as the signed-in
  user (the RPC re-checks the admin role and writes the audit row with the `dismissal_id`, never the reason).
- "Dismissal history" card: the last 10 dismissals (deal, reason, when, who, current state: Dismissed / Restored /
  Dispatched). Names come from the org's own members' profiles (service role, after requirePerm).
- Phone: the table becomes one card per deal (labels from `data-label`), same DOM.

### /admin/stock/dispatch (stock.dispatch; plan 7.4)
- Modes: "Without sequence number" (free) and "Existing sequence number" (Deal year default this year, Sequence
  number, **Find unit**). `?year=&number=` opens the second mode with Find unit already run.
- Find unit outcomes (`findOutcome`): found and outstanding -> "Deal 2026 / 260 · 1000DB · Cape Town. Add or confirm
  the VIN and destination." and prefill of model, branch and accessories (unknown model: "Model not recognised on the
  DEAL: choose the model."); dismissed -> "This deal has been dismissed. Only an admin can restore it before
  dispatch."; already dispatched -> "Deal 2026/260 was already dispatched with VIN X."; not found -> "No matching deal
  for this year and number.". Every outcome but found disables **Complete dispatch →**, as does changing the year or
  number after a find.
- Fields: Model / part number ("PART — description", active models), VIN (checked on blur against every unit, sold
  included: duplicate copy from the plan, or a note when the VIN is an unsold Factory unit), Destination branch
  (Factory allowed in free mode only: a deal clears when its unit reaches a branch), Dispatch date (default today in
  the org timezone), 10 accessory lines (01-10), Dispatch notes. Footer "VIN is checked against all records,
  including sold units."
- Server action `dispatchUnit`: requirePerm('stock.dispatch') -> `parseDispatch` (Zod, pure) -> `stock_dispatch_unit`
  as the signed-in user -> errors mapped with `lib/stock/errors.ts` and placed under their field (`errorField`).
  `FACTORY_UNIT_EXISTS` shows "Move this factory unit to {branch}" (`moveFactoryUnit` -> `stock_move_unit` Factory ->
  branch, with the deal year/number in deal mode so the deal clears; the unit keeps the model, accessories and notes
  recorded at the Factory). Success redirects to `/admin/stock/units?q={VIN}&saved=dispatch|move`;
  `savedNotice(sp.saved)` (`lib/stock/dispatch.ts`) gives the confirmation copy ("Dispatch saved.") for the Units page.
- Works at 390px: one column, full-width 52px submit, radio cards instead of a segmented control.

### Review fixes
- Model detection: exact PARTNO match first (any line), then the part before a suffix (`CTLL1-GWM`, `3000D/RED`, same
  separators as `isModelItemCode`); that line is not stored as an accessory.
- Out-of-scope deals are removed only through `stock_remove_untouched_deal` (0016, service role): one DELETE that also
  requires no dismissal rows, no unit and no stock audit row naming the deal (a deal relinked away by
  `stock_correct_unit` keeps its history).
- "Rebuild deals" (`enqueueDealsBackfill`) always queues a fresh pass from the first DEAL unless one is already pending;
  a pending continuation of an older pass stops itself once a fresh pass is queued.
- Outbox handlers receive `{ deadline }` from `drain()`; the backfill caps its budget to it (`backfillBudget`: at most
  20 s, 3 s margin, at least 1 s) and checks the deadline after each entry.
- Deals page: a page past the end shows the last page (PostgREST answers 416; the e2e stub now does too);
  "Refresh dismissals" reloads the same view. Find unit compares year and number as numbers ("0260" = 260).

### Assumptions / open questions
- Dismiss/restore copy names "an admin" (the plan names its superuser, Gerald).
- Deleting a DEAL entry keeps its stock deal (`entry_id` becomes null); an admin can dismiss it. Removing it
  automatically is a possible follow-up.
- The deal sync runs for every DEAL save action (Submit, Update, Action); drafts are never deals.
- The Units page (other branch) should render `savedNotice(searchParams.saved)` so the redirect shows "Dispatch saved.".
