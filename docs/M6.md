# M6: Stock control (units by VIN, dispatch, branch matrix, invoice to reserved/sold)

Source: `docs/source/BUILD_PLAN_trailer_stock.md` (the ChatGPT review build, reverse engineered). That plan describes a
stand-alone app. This platform already has most of what it builds from scratch, so M6 maps it onto what exists.
**Design is ours**: the UI-step-1 tokens and `components/ui` (see CLAUDE.md "Repo notes (UI handoff, step 1)"), not the
review build's teal look. Copy (messages, labels) follows the stock plan where it specifies text.

## 1. What changes from the stock plan

| Stock plan | M6 |
|---|---|
| Cognito webhook feeds `deals` | Derived from our own **DEAL** entries (job on DEAL Submit/Update + backfill). No Cognito webhook. |
| Make / Xero webhook feeds invoices | Derived from the **Xero mirror** (`xero_invoices`) after each sync/webhook upsert. No Make. |
| Own auth, `profiles`, roles superuser/admin/dispatcher/branch | Our orgs, memberships, `can()`. Superuser = `admin`. New role `factory` (dispatch). Branch scoping deferred. |
| `activity`, `deal_audit` tables | `audit_log` (append-only, ids only) with `stock.*` actions; the Activity page renders it. |
| `integration_deliveries`, Connections page, webhook secrets | Not needed: Xero integration page already shows sync state. |
| `app_settings` singleton (`integration_live`) | Org `app_settings` keys `stock.*` (server-only writes, like 0009). |
| Simulated / manual invoice form | Manual apply kept for admins (invoice not in Xero yet), same rules, audited. |
| Single-tenant tables | Every table org-keyed with RLS (CLAUDE.md non-negotiable 2). |
| `customer_name` on deals | Not stored. Stock tables hold no personal data (DEAL is an encrypted form). |

## 2. Data (migrations)

- `0010_stock_role.sql`: `alter type app_role add value 'factory'` (alone: a new enum value cannot be used in the same transaction).
- `0011_stock.sql`:
  - `stock_locations(org_id, id text, name, is_factory, sort_order)`: FACTORY, JHB, CPT, DBN seeded for the default org.
  - `stock_models(org_id, part_number, description, category, active, sort_order)`: the 52 models in the plan's order and spelling (keep "SINGEL", "CRADEL", "Dubbel axel").
  - `stock_deals(id, org_id, entry_id -> entries, year, number, location_id, model_part, quote_number, accessories text[] <= 10, status awaiting_dispatch|dispatched|dismissed, unit_id, dismissed_reason, dispatched_at, created_at, updated_at)`; unique (org_id, year, number), unique (org_id, entry_id).
  - `stock_units(id, org_id, vin, vin_norm generated upper(regexp_replace(vin,'\s','','g')) unique per org, deal_year, sequence, deal_id, model_part, location_id, status available|reserved|sold, invoice_number unique per org when not null, xero_invoice_id, dispatch_date, accessories text[] <= 10, notes, sold_at, created_by, created_at, updated_at)`.
  - `stock_invoice_exceptions(id, org_id, xero_invoice_id, invoice_number, reference, reason, unit_id, created_at, resolved_at, resolved_by, resolution)`; unique open exception per (org, invoice, reason).
  - RPCs (security definer, `set search_path = ''`, check membership + role inside, write `audit_log`): `stock_dispatch_unit`, `stock_move_unit` (factory to branch / transfer), `stock_correct_unit`, `stock_dismiss_deal` / `stock_restore_deal` (admin only, reason required), `stock_apply_invoice` (used by the job and the manual form). Error codes as in the stock plan section 6.1 (`VIN_EXISTS`, `DEAL_NOT_FOUND`, `DEAL_DISMISSED`, `DEAL_ALREADY_DISPATCHED`, `VIN_NOT_FOUND`, `UNIT_LINKED_OTHER_INVOICE`, `INVOICE_LINKED_OTHER_UNIT`).
  - Clients: select for org members (stock.read); no direct insert/update/delete on stock tables; writes only through the RPCs or the service role after `requirePerm`.
  - View `stock_matrix` (security_invoker): per model x location qty (available + reserved) and reserved count, sold excluded.
- Every new table goes into `tests/db/rls.test.ts`.

## 3. Rules (pure, `lib/stock/*`, unit tested)

- `normalizeVin`, `extractVin(reference, knownVins)` (exact normalised match first; else the one known VIN contained in the reference; else none/ambiguous).
- KPIs (plan 5.2): stock across branches (branch, available|reserved), ready to sell, reserved, at factory (not sold); sold excluded everywhere but searchable.
- `dealFromEntry(data, entry)`: year = year of `DATECREATED` (fallback: entry created date, Africa/Johannesburg); number = DEAL entry number; location from `COLLECTIONLOCATION` (JHB->JHB, DUR->DBN, CPT->CPT); model = first `PARTNO1..8` matching a model part number (case/space-insensitive); accessories = the other non-empty `LINE` descriptions, max 10; quote = `QUOTENO`. ASSUMPTION: the stock plan's "sequence number" is the DEAL entry number. Unknown model -> deal shows "Model not recognised" and dispatch asks for the model.
- `invoiceOutcome(invoice, unit)`: AUTHORISED/SUBMITTED with amount due > 0 (incl. partly paid) -> reserved; PAID (amount due 0) -> sold; VOIDED/DELETED, credit notes, missing/unknown/ambiguous VIN, unit linked to another invoice, invoice linked to another unit -> exception, no change. DRAFT -> ignored.

## 4. Settings ("Pilot setup", `/admin/stock/setup`, admin)

- `stock.deals_from` (date): only DEAL entries created on/after it become stock deals. Unset = no deals imported (avoids ~550 historical deals showing as outstanding).
- `stock.invoice_rules`: `off` | `preview` | `live`, default **preview**: the job records what each invoice would do (shown on Invoice review) but changes no unit. `live` needs a typed confirmation and is audited (same pattern as Xero actions, server-only writes).
- Opening stock: CSV upload (VIN, model, location, status, invoice, deal year, sequence, dispatch date, notes) -> dry-run report (counts, duplicate VINs, unknown models/locations) -> apply. Idempotent on VIN.
- "Rebuild deals" button (enqueue the backfill job).

## 6. Jobs

- `stock.deal-sync` (payload: entry id) enqueued from `afterSave` for DEAL Submit/Update; `stock.deals-backfill` (all DEAL entries since `stock.deals_from`, resumable).
- `stock.invoices` after each sync/webhook upsert batch (invoice ids) and nightly: applies `invoiceOutcome` per `stock.invoice_rules`; idempotent (same invoice state twice = no-op).
- All jobs record `job_runs`, never log VINs with personal data (VINs are not personal data; customer details never touched).

## 7. Permissions

`stock.read` (admin, staff, reviewer, factory), `stock.dispatch` (admin, staff, factory), `stock.export` (admin, staff), `stock.manage` (admin: dismiss/restore, correct, transfer, manual invoice, exceptions, setup).

## 8. Acceptance (from the stock plan, adapted)

Duplicate VIN blocked incl. sold; dispatch against a deal clears it; dismissed deal blocks dispatch; already dispatched deal blocks a second dispatch; dispatch without a deal never clears a deal; unpaid -> reserved stays in counts with amber marker; paid -> sold leaves counts but stays searchable; unit linked to another invoice -> exception, no change; voided invoice -> exception; preview mode changes nothing; non-admin cannot dismiss/restore or change setup (server and RLS); cross-org isolation on every stock table; DEAL submit creates exactly one stock deal (resubmit/update updates it).

## 9. Open questions (defaults in brackets; rules are switchable)

1. Voids/credit notes on a reserved or sold unit [exception queue, no automatic change].
2. Partial payment threshold [any amount due > 0 = reserved].
3. Branch transfers and returns to factory [admin transfer with audit].
4. Branch users see only their branch [no, all branches].
5. Is the stock "sequence number" the DEAL entry number, and does the year come from DATE CREATED [yes, yes].
6. One deal = one unit [yes].
7. Factory units registered before a deal exists [yes: dispatch to Factory, later move to a branch].
8. "Pilot setup" in the review build: confirm it is the start date + opening stock + rule mode [assumed].
