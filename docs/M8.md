# M8: Form builder (create and edit forms in the app)

Asked for: "option to create forms", "proper form builder with all fields possible and required", and
"option to import forms". Forms are already data: `forms.spec` (FormSpec, `lib/spec/types.ts`) drives the
renderer, validation, workflow, emails, PDFs, grids and exports. M8 adds the field types and per-field
options a real builder needs, then a builder UI that writes valid specs.

## Part A: engine (lib/spec, components/form-engine, lib/pdf, lib/admin)

### Field types (palette)

| Type | Notes |
|---|---|
| text | single line; placeholder, min/max length, pattern presets (none, letters/numbers, uppercase) |
| textarea | rows, max length |
| email | existing (required/default/protected) |
| phone (new) | tel input, stored as typed + digits-normalised for search; min 9 digits |
| url (new) | https only |
| number | existing integer/decimals; min/max |
| currency (new) | amount + currency code (non-negotiable 7); default org currency; stored `{ amount, currency }` |
| date | existing; default "today" (done) |
| time (new) | HH:MM, org timezone |
| datetime (new) | date + time, stored UTC, shown in org timezone |
| yesno (new) | Yes/No toggle or radio |
| choice | dropdown / radio / checkboxes, multi, default, "Other" option (new, free text) |
| name | existing parts (first/last; optional title/middle) |
| address | existing parts |
| file | existing multi/max files/accept |
| signature | existing |
| lookup | existing: pick an entry of another form |
| rating (new) | 1-5 |
| section (heading) | title + optional description; groups following fields |
| content | rich text block (sanitised HTML allow-list) |
| pagebreak | existing |

`table` and `checklist` stay supported for the kit forms but are not in the builder palette (v1).

### Options on every input field

`required` (all input types, validated server-side in `validateEntry`), `label`, `hideLabel`, `help`
(note under the field), `placeholder` (text-like), `default` (type-appropriate), `readOnly` (shown, not
editable by the public role), `internalOnly` (hidden on the public form, staff only), `showWhen`
(conditional visibility using the existing expression engine, e.g. `MONTH = "JAN"` or `YesNo1 = true`;
hidden fields are not validated and not saved), layout `row`/`col`/`span` (24-col grid). Field `name` is the
storage key: generated from the label once, never renamed after the form has entries (CLAUDE.md rule).

Renderer, `readFormData`, `validateEntry`, `displayValue`, summary template, grid columns, CSV/XLSX export,
entry PDF and search text must all handle every type. Existing kit specs must parse and behave unchanged
(tests compare before/after for all 7 kit forms).

### Part A: built (engine)

All in `lib/spec` (pure, unit tested in `tests/unit/form-engine-types.test.ts`), rendered by
`components/form-engine` on top of the UI handoff renderer (`lib/spec/presentation.ts` cards and steps).

**Spec additions (zod, `lib/spec/types.ts`, all optional so the kit specs parse unchanged):**

- Every input field (text, textarea, email, phone, url, number, currency, date, time, datetime, yesno, rating,
  choice, name, address, file, signature, lookup) takes `required`, `help`, `readOnly`, `internalOnly`,
  `showWhen` (plus the existing `label`, `hideLabel`, `row`/`col`/`span`). `note` stays an implementer's note
  and is never shown; `help` is the text under the field.
- `placeholder`: text, textarea, email, phone, url, number, currency. `minLength`/`maxLength`: text,
  textarea. `min`/`max`: number, currency (numbers), date (YYYY-MM-DD), time (HH:MM). `rows` (1-30): textarea.
  `pattern`: text, `none | alphanumeric | uppercase`.
- `default`: text/textarea/email/phone/url string; number/currency number; date `'today'` or YYYY-MM-DD;
  time `'now'` or HH:MM; datetime `'now'`; yesno boolean; rating 1-5; choice string.
- New types: `phone`, `url`, `currency` (`currency?: 'ZAR'`-style code), `time`, `datetime`,
  `yesno` (`style?: 'radio' | 'toggle'`), `rating`. `choice.other: boolean` adds "Other" with a text box.
- `section` without `children` is a heading (`label`, `description?`, `showWhen?`); the kit checklist section
  keeps `children`. `content` takes `showWhen` too.
- `FormSpec` refuses: a `showWhen` that does not parse, names an unknown field or depends on itself through
  other rules or its heading (cycle); a slug in `RESERVED_FORM_SLUGS` (`import`, `new`, `design`, `create`,
  `settings`, `export`, `entries`, `versions`, `archive`, `archived`, `templates`, `builder`; route segments
  next to `/admin/forms/<slug>`; add any new fixed segment there).

**How each type is stored, validated, displayed, exported and printed**

| Type | Stored in entries.data | Validated (readFormData / validateEntry) | Displayed (grid, email, PDF, summary) | Export (CSV/XLSX) |
|---|---|---|---|---|
| phone | `{ phone: "as typed", digits: "0820000001" }` | `+`, digits, spaces, `()-.`; 9-15 digits | as typed | as typed |
| url | normalised string, https only (a bare host gets `https://`) | https, a dotted host, no credentials, max 2000 | the link | the link |
| currency | `{ amount, currency }` (field code, else org currency, else USD) | amount with up to 2 decimals (spaces/commas ignored), min/max | `formatAmount` from `lib/money/fx` ("R 1,500.50", "$26.00", "EUR 3.00") | two columns: `<label>` = amount (2 dp), `<label> currency` = code |
| time | `"HH:MM"` (wall clock) | HH:MM, min/max | as stored | as stored |
| datetime | UTC ISO instant | `YYYY-MM-DDTHH:MM` entered in the org timezone (`lib/spec/time.ts`) | `YYYY-MM-DD HH:MM` in the org timezone | same |
| yesno | `true` / `false` | radio: yes/no/blank; toggle: on = true, off = false | Yes / No | Yes / No |
| rating | integer 1-5 | 1-5 | `4/5` | `4` |
| choice + Other | the typed text (single) or appended to the list (multi) | listed options; Other needs text (max 500) | as stored | as stored |
| section heading | nothing | not validated | a section card (web) / bold heading + description (PDF); not in grid, export or emails | not exported |

`required` works on every input type (file and signature count their files; name needs every part; address any
part; a required toggle must be on). Search: the grid searches `entries.search_text` (summary + data JSON), so a
phone is found by what was typed or by its digits; datetimes are searchable by their stored UTC text only.

**Show-when (`lib/spec/expressions.ts` `parseShowWhen`, `lib/spec/visibility.ts`)**: `Field = "text"`,
`== != <>`, `> >= < <=` (numbers, or text compare for dates/times), `= true/false`, `contains "x"` (list item or
case-insensitive text), `is empty` / `is not empty`, `AND` (binds first), `OR`, parentheses; keywords any case.
Currency compares its amount, phone what was typed, multi choices any item. A field is hidden when its rule is
false or its heading is hidden; a hidden field reads as empty for other rules. Hidden fields are not validated,
not saved (dropped from data on every save, also by staff), their read errors are ignored, and their files are
left as they are. The browser runs the same functions (`checkPost` before posting, `hiddenFields` on every
change), so a field shows and hides live and required is enforced before anything is posted.

**readOnly / internalOnly** (`prepareSave`, `lockedFor`): for the public role (public link and role links)
both keep the saved value (or the default on a new entry) whatever is posted, are not validated, and their
files are left alone. readOnly fields are shown read-only; internalOnly fields and values are stripped from
the spec and data sent to the browser (`publicSpec`, `publicData`). Staff (and system jobs) edit both.
Email entry details leave internalOnly fields out when the email goes to an address taken from the entry
(`[Field]` recipient); the entry PDF is the staff record and includes them.

**runAction** reads with the org timezone and currency, then `prepareSave` (locks + show-when), `planFiles`
with the skip set, `validateEntry(..., { skip })`; the summary renders typed values (`renderSummary(t, data,
{ spec, timeZone })`).

**Renderer**: phone `tel`, url `url`, time, `datetime-local` (shown in the org timezone), currency with its code
in front, yes/no as the kit's pills or a switch (`role="switch"`), rating as five star radios (radiogroup),
choice Other as one more pill / option with a text box. `help` is linked with `aria-describedby`; required
fields show the * and carry `aria-required`. Headings become section cards (their rule hides the card).
`audience="public"` on `/f/<slug>` and `/e/<token>`; `timeZone` and `currency` come from the org.

**Rich content**: `content.html` goes through an allow-list (`htmlBlocks`): p/div/br, h1-h6, strong/b, em/i,
ul/ol/li, `a href` https/mailto only; everything else is dropped (script/style with their content). The result
is the block model, never HTML. The kit snippets come out unchanged.

**Kit forms unchanged**: `tests/unit/kit-forms-unchanged.test.ts` compares all 7 kit forms (pages, read,
validate, defaults, summary, display, grid columns, export, email rows, three renderer variants, PDF) with
`tests/fixtures/kit-forms/baseline.json`, written from the UI branch engine at 617699f before any M8 change.
The one allowed markup difference is `aria-required="true"` on required inputs (normalised in
`kit-snapshot.ts`). Regenerate only for an intended kit change: `KIT_BASELINE=write pnpm test tests/unit/kit-forms-unchanged.test.ts`.

**e2e**: `tests/e2e/form-engine-types.spec.ts` inserts `tests/fixtures/m8/engine-types.json` (every type,
required, show-when on a field and on a heading, Other, rich content, internalOnly, readOnly) by SQL, submits it
publicly (client-side required/show-when with nothing posted; a tampered post refused by the server; forged
readOnly/internalOnly values ignored), checks the stored data, the grid (incl. search by phone digits), a staff
edit, the CSV export and the entry PDF text.

**Notes for Part B**

- A builder form needs a `cognitoFormId` (int; use 0) and a slug that is not reserved (`isReservedFormSlug`).
- `lib/spec/presentation.ts` packs consecutive narrow rows of simple inputs side by side (a fix for Cognito
  layouts). For builder forms the author sets widths and "same row"; consider turning packing off for forms
  without a `PRESENTATIONS` entry that came from the builder.
- `settings.entrySummary` tokens render typed values (`[Phone]` shows what was typed).
- `parseSpec` already rejects bad show-when rules; the builder only needs to offer field names and literals.

## Part B: builder UI (`/admin/forms`, permission `forms.manage`)

- **Create form**: blank, duplicate an existing form (copies spec, no entries), or **import a form**
  (upload a FormSpec JSON exported from here or the kit). Name -> slug (unique per org, editable before
  publish). Options: public link on/off, encrypt entries (only before the first entry), entry summary
  (pick fields), numbering starts at 1.
- **Designer** (`/admin/forms/<slug>/design`): left palette of field types; canvas showing fields in
  order with drag-and-drop reorder (plus up/down buttons for keyboard and phone); click a field to edit its
  options in a side panel; "same row as previous" + width (full, 1/2, 1/3, 1/4); page breaks and sections;
  live preview with the real `FormRenderer` (desktop and phone width); undo for the last change.
- **Workflow tab**: statuses (name, colour, archived), roles (public / internal), actions (button label,
  allowed when: status is one of ..., new status, confirmation text), notification emails per action
  (recipients, subject, include entry details / PDF / files, link for a role). Templates: "Public submit,
  staff update" (default) and "Internal only".
- **Documents tab**: entry PDF on/off, title/logo, include blank fields.
- **Drafts, publish, history**: edits save to a draft; Publish validates (parseSpec + builder rules) and
  bumps the version; `form_versions` keeps every published spec (append-only, who/when/note); a version can
  be restored as a new draft. Guards: cannot delete or rename a field that has data (archive/hide instead),
  cannot change a field's type incompatibly once it has data, cannot turn encryption off once entries exist.
- **Export JSON** for any form; **Archive form** (hidden, entries kept); kit forms can be edited with the
  same guards.
- Migration `0018_form_builder.sql`: `forms.org_id` scoping for slugs if needed (unique per org),
  `forms.draft_spec`, `forms.version`, `forms.archived_at`, `form_versions` (RLS: org members read; writes
  via server only), statuses/roles rows synced from the published spec.

## Acceptance

Create a form with every palette type, required fields and a show-when rule; publish; submit it publicly
(required and show-when enforced client and server side); entry appears in the grid, export and PDF with
every value; edit the form (add field, reorder, relabel) and old entries still render; renaming/deleting a
field with data is refused; export JSON and import it as a new form; version history and restore; staff
without `forms.manage` cannot reach the builder (server refuses); all 7 kit forms unchanged.
